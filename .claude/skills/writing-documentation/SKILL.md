# Writing Documentation

ドキュメントを新規作成する際のワークフローを実行する。

## ワークフロー

このチェックリストをコピーして進行状況を追跡する：

```
タスク進捗：
- [ ] ステップ1: 規則を確認する
- [ ] ステップ2: 見出し構造を設計する
- [ ] ステップ3: 見出し構造をレビューする
- [ ] ステップ4: 内容を書き出す
- [ ] ステップ5: 全体をレビューする
```

**ステップ1: 規則を確認する**

[docs/README.md](../../../docs/README.md) を読み、以下の規則を確認する。

| 項目 | 内容 |
|------|------|
| 命名 | ファイル名・ディレクトリ名 |
| 構成 | テンプレート・ポイント |
| 配置 | 判断基準・フロー |
| 文体 | 敬体・常体、文末表現、漢字の開き |

**ステップ2: 見出し構造を設計する**

ドキュメントの骨格となる見出し構造を設計する。

- 概要から始め、詳細へ展開する流れを意識
- 読者が最も参照する情報を中心に配置
- 補足的な情報は後半に配置

成果物: 見出し一覧（箇条書きまたはツリー形式）

**ステップ3: 見出し構造をレビューする**

設計した構造の妥当性を検証する。

| 観点 | 確認内容 |
|------|----------|
| 論理的順序 | 前の見出しが次の見出しの前提になっているか |
| 重複排除 | 同じ内容が複数の見出しに分散していないか |
| 粒度の統一 | 見出しの抽象度が揃っているか |

問題がある場合はステップ2に戻って修正する。

**ステップ4: 内容を書き出す**

各見出しの内容を記述する。

原則:
- 簡潔に書く（冗長な説明を避ける）
- 表・箇条書き・コード例を活用
- 実務で参照しやすい形式を優先

成果物: ドキュメント全文

**ステップ5: 全体をレビューする**

完成したドキュメントを俯瞰して検証する。

| 観点 | 確認内容 |
|------|----------|
| 断絶 | 見出し間で内容が途切れていないか |
| 流し読み | 斜め読みで要点が把握できるか |
| 一貫性 | 全体を通してテーマが維持されているか |

問題がある場合は該当箇所を修正する。
